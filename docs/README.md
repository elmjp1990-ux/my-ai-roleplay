## 目前狀態（2026-10-15）

### 最高優先：聊天扣款與退款安全
- **狀態：功能分支已有部分原始碼，尚未完成整合及驗收。**
- 已修正發送訊息流程：雲端保存失敗時，會還原本機新增的回覆與回憶，避免顯示成已完成。
- 已新增錢包扣款 RPC SQL 草稿、固定示範回覆 Edge Function 原始碼，並把功能分支前端接到該函式；另已降低回覆保存結果不明時的誤退款風險。SQL 尚未套用、函式尚未部署，因此正式網站仍不會執行這套扣款。
- 已確認規則：每個新生成回合總成本 2 點；先扣銀幣，不足部分用鑽石；先預扣，只有非空回覆已成功保存到雲端並確認結算後才算完成扣款；確定失敗時按原銀幣／鑽石比例退款一次。
- 餘額不足：不呼叫生成、不扣款，提示觀看獎勵影片。
- 重試、雙擊、跨分頁必須以穩定 turn ID 冪等處理；不明確的逾時先查證／對帳，不可盲目退款或重複生成。回覆寫入結果不明或同時有重試時，先保留待對帳狀態，不因單次查無回覆就退款。
- 編輯上一則使用者訊息但不重新生成：免費。
- 目前網站仍使用固定示範回覆，尚未串接真正 AI。已同意可用示範回覆驗證扣款流程。
- **安全邊界：** 尚未套用資料庫 migration、未合併 main、未部署；任何正式資料庫變更、合併及部署都須另行確認。

### 次要：ayeT 獎勵影片回呼

## 維護規則（避免文件膨脹）

1. **先更新既有文件，不為每個小修正新建文件。**
2. 本頁只保留決策、真實狀態、風險、下一步與文件連結；詳細 SQL／狀態機／測試案例放在對應技術文件。
3. 一項需求只設一個主要追蹤項目。子任務放在同一份檢查清單，不要重複建立專案項目。
4. 每次有實際進展時，只同步更新：本頁的狀態／下一步、對應檢查清單，以及必要的技術細節。
5. 明確區分「已檢查」「已寫程式」「已套用資料庫」「已合併」「已部署」「已驗收」；文件或草稿存在不代表功能已完成。
6. 過時方案先標示為「已取代」並連結新方案；只有確認無引用、無稽核價值時才刪除，避免失去決策歷史。
7. 任何正式資料庫修改、合併 main 或部署前，先列出影響與回復方式並取得專案負責人確認。
