> **唯一維護入口。** 開始工作先看本頁；以本頁的「目前狀態」和專案進度表為準。附屬文件只存放必要的技術細節，不得自行形成另一套規則。

## 目前狀態（2026-10-15）

### 最高優先：聊天扣款與退款安全
- **狀態：正式資料庫 migration 與固定示範回覆 Edge Function 已部署；尚未完成端到端驗收。**
- 正式 Supabase 已套用 migration `wallet_chat_turn_charging`；已確認 `chat_turn_charges`、`chat_turn_events`、冪等交易索引，以及預扣／結算／退款 RPC 存在。
- 正式 Supabase 的 `chat-turn` Edge Function v1 狀態為 ACTIVE，且已啟用 JWT 驗證。部署版本使用固定示範回覆，**不會呼叫真正 AI API**。
- 功能分支前端已串接 Edge Function，但尚未合併至 main／正式網站，也尚未完成實際端到端測試。
- 已確認規則：每個新生成回合總成本 2 點；先扣銀幣，不足部分用鑽石；先預扣，只有非空回覆已成功保存到雲端並確認結算後才算完成扣款；確定失敗時按原銀幣／鑽石比例退款一次。
- 餘額不足：不呼叫生成、不扣款，提示觀看獎勵影片；獎勵影片本身尚未設定完成。
- 重試、雙擊、跨分頁必須以穩定 turn ID 冪等處理；不明確的逾時先查證／對帳，不可盲目退款或重複生成。回覆寫入結果不明或同時有重試時，先保留待對帳狀態，不因單次查無回覆就退款。
- 已新增「固定示範回覆專用」逾時對帳 SQL 草稿；**尚未套用、排程或驗證**。另外發現既有 `chat_messages_update_own` RLS 允許使用者更新自己的聊天訊息，而目前正式觸發器只攔截 assistant INSERT，未保護已扣款回覆的內容不被後續 UPDATE 修改；已新增 source-only UPDATE 防護草稿，尚未套用。接入真正 AI 前，必須先改成查詢供應商／生成工作狀態的安全對帳，不能直接使用示範模式的逾時退款規則。
- 編輯上一則使用者訊息但不重新生成：免費；重新生成視為新回合。
- **安全邊界：** 未合併 main、未部署前端、尚未完成併發／退款實測。正式資料庫變更、合併及部署仍須另行確認。

### 次要：ayeT 獎勵影片回呼
- **狀態：草稿／未設定完成。**
- Publisher 已可登入，但網站審核、Placement／AdSlot 核准、回呼簽章與實際測試尚未全部確認。
- 回呼端點目前是 fail-closed scaffold，不會發放獎勵。未完成簽章驗證、交易去重及測試前，不得部署或設定正式回呼。

## 維護規則（避免文件膨脹）

1. **先更新既有文件，不為每個小修正新建文件。**
2. 本頁只保留決策、真實狀態、風險、下一步與文件連結；詳細 SQL／狀態機／測試案例放在對應技術文件。
3. 一項需求只設一個主要追蹤項目。子任務放在同一份檢查清單，不要重複建立專案項目。
4. 每次有實際進展時，只同步更新：本頁的狀態／下一步、對應檢查清單，以及必要的技術細節。
5. 明確區分「已檢查」「已寫程式」「已套用資料庫」「已合併」「已部署」「已驗收」；文件或草稿存在不代表功能已完成。
6. 過時方案先標示為「已取代」並連結新方案；只有確認無引用、無稽核價值時才刪除，避免失去決策歷史。
7. 任何新增正式資料庫修改、合併 main 或部署前，先列出影響與回復方式並取得專案負責人確認。
