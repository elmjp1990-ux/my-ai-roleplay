# GROUP-01 核心功能驗收與測試案例

> 狀態：測試規格草案。前端 mock 群組流程已接入 `index.html` 路由，但尚未完成瀏覽器操作測試；未連線正式 AI、未執行資料庫 SQL。

## 測試範圍與原則

- 先以固定的 mock 導演結果驗證流程；AI provider 接入另行驗收。
- 前端目前只負責操作體驗與初步限制；所有權、已審核公開角色、群組人數限制必須在資料庫／伺服器端再次驗證，不能只靠前端。
- 群組建立失敗不得留下半套群組、場景或成員資料。
- 本階段 mock 群組流程不得呼叫既有單人聊天扣款流程，也不得修改錢包餘額。群組計費需另行設計冪等交易邊界後再接入。
- 角色快照只存可供聊天顯示與敘事使用的必要公開欄位；不得把 `privateInfo`、作者私有備註或其他秘密欄位複製進快照。

## 建立流程（3 步驟）

1. **群組基本資料**：群組名稱必填、長度與字元規則需與現有網站命名規則一致。
2. **世界背景與場景模式**：輸入世界背景，選擇「同一場景」或「分開場景」；至少要有一個有效場景。
3. **選擇角色並確認**：只能選擇登入者有權使用的角色；至少 1 名、最多 3 名；提交後顯示建立結果與成員。

## Mock 導演輸入／輸出契約（建議）

輸入至少包含：群組 ID、回合 ID、世界背景、場景模式、目前場景、成員快照、最近的群組訊息，以及每位角色的場景關聯。

輸出應為結構化資料，而非任意 HTML：
- `turnId`：本回合冪等識別碼。
- `speakerCharacterId`：必須是該群組成員之一。
- `sceneId`：必須屬於該群組，且符合場景模式。
- `content`：純文字敘事內容，由 UI 進行 HTML escaping。
- `sequence`：由伺服器分配或驗證，不能信任客戶端提供的順序。
